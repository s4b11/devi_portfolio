# Agent instructions

## Before starting

1. Read [the knowledge index](okf/index.md) and [current state](okf/current-state.md).
2. Follow the links to the architecture, features, decisions, and development notes relevant to the task. Read applicable nested instructions.
3. Check the relevant source, tests, approved requirements, and issue records before relying on a claim. Flag discrepancies and distinguish intended, implemented, proposed, and historical behavior.
4. Check Git status and preserve unrelated work. Scope edits to the task and follow applicable decisions and conventions.

## During work

- Record significant changes to behavior, interfaces, data, architecture, dependencies, and operations, along with consequential decisions and their rationale.
- Correct stale claims once verified. For lengthy or interrupted work, checkpoint verified progress, open questions, and the next action in the relevant concepts and current state.
- Use source and tests as evidence for implementation, approved requirements for intent, and the issue tracker for task ownership and priority. Link to original evidence where available.

## Before handing off

1. Run applicable builds, tests, linters, or documentation checks. Record actual results, limitations, and outstanding verification.
2. Update affected concepts, decision records, and development notes. Update current state when work, blockers, risks, or next actions change. Add a dated log entry for meaningful changes and refresh affected indexes when their contents change.
3. Check YAML, links, provenance, verification, and lifecycle metadata. Preserve superseded decisions with links to their replacements and keep secrets, sensitive data, transcripts, and duplicate knowledge out of the bundle.
4. Keep current-state claims within the branch they describe. Reconcile shared indexes, state, and log against the merged implementation and approved requirements during integration. Review knowledge changes alongside related code and use Git for full history.
5. Report completed work, checks and results, knowledge updates, unresolved work, and the next useful action.
